# 画布职责边界

## 当前接口

- `VpCanvas` 是 Qt Quick 视图：接收控件坐标和键鼠事件，转换为图像坐标，绘制场景与临时辅助层。它只向 QML 暴露 `controller` 属性，通过 `update()` 请求重绘。
- `VpController` 拥有 `VpDocument`、画笔和图章工具。QML 通过控制器选择工具、设置工具参数和执行粘贴命令，也从控制器接收状态提示。绘画命令的输入和输出均使用图像坐标；控制器管理一次笔触的文档事务与撤销记录，并提供预览所需的只读查询。控制器不依赖 `QQuickItem`，也不调用 `VpCanvas`。
- `VpDocument` 保存背景、平面、绘画层、浮动图像和历史。它不接收指针事件，也不绘制。
- `SceneRenderer` 从文档绘制屏幕内容与离屏合成内容。屏幕绘制和仿制源、选区取样、浮动图像烘焙共用这条渲染路径。

目前平面、选区和浮动图像的交互仍在 `VpCanvas`，通过 `m_doc` 引用访问控制器持有的文档。这是迁移期间的接口；后续迁移完成后，视图只应通过控制器的命令修改文档。

## 后续迁移顺序

1. 把平面创建、编辑和角度调整移入控制器；视图只传图像坐标与键盘修饰符，并根据返回状态刷新界面。
2. 把浮动图像的命中、拖动、吸附和烘焙移入控制器，统一管理编辑事务。
3. 把选区的曲面坐标、复制和填充移入控制器。选区轮廓及控制点的绘制继续由视图和渲染器负责。
4. 移除 `VpCanvas` 中的 `m_doc` 过渡引用；保留文档只读访问供渲染器使用。
