# 消失点画笔绘制性能：定位、实现与对照验证

日期：2026-10-13。基线：选区优化完成后的 `55830b7b9`。

本次优化已实现，生产代码提交为 `bb70bb425`。本报告、原始数据和构建日志放在本地排除目录，不提交 Git。

## 卡顿来自哪里

连续绘制时，pointerMove 原来会发出通用 repaintRequested。尽管画笔只修改很小的一块像素，VpCanvas 仍会重新绘制整张背景和绘画层，光标预览也使用整幅视图的透明图像项。

首次落笔另有一笔大开销：beginPaintTransaction 浅拷贝整张绘画层作为撤销快照。随后 QPainter 写入共享 QImage，触发整图 detach。4K 的 ARGB32 像素为 64 MiB，8K 为 256 MiB，这些像素会在第一笔写入时复制。

笔刷本身还会根据移动距离插入多个 dab，并逐个进行透视投影、径向渐变和抗锯齿绘制。本次保留这套算法和全部输入点，以保证笔触输出一致。

## 实现

### 独立绘画层与局部刷新

```text
VpCanvas                      缓存背景
├─ PaintLayerItem              绘画层，笔刷更新只刷新脏矩形
├─ FloatingContentItem         Ctrl 克隆临时图像
├─ FloatingContentItem × N     已有浮动图像
├─ CursorPreviewItem           画笔局部预览 / 图章预览
└─ AuxiliaryOverlayItem        平面、选框及控制点
```

控制器从 BrushTool 获得本次所有 dab 的脏矩形，发送 paintRepaintRequested(dirty)。Canvas 将其变换到视图坐标，向外扩展 2 像素并裁到可见范围，再调用绘画项 update(region)。空矩形不调用 update，避免 Qt 把空矩形解释为整项刷新。

画笔光标的图像项也裁到当前投影笔刷的可见范围；移动时更新项目的位置和图像。背景只在背景像素或视图改变时刷新。缩放、滚动、窗口尺寸改变会重绘完整绘画项；撤销、重做、文档替换等通用内容变化保留整绘画层刷新路径。

PaintLayerItem 在 Qt 绘制时读取文档中的绘画层，不持有一份浅拷贝，避免显示层每帧又造成整图 detach。图章和烘焙等操作继续使用通用绘画层刷新，本次没有将它们改为局部事务。

### 撤销快照按首次触及的像素块保存

画笔开启增量绘画事务。每个 dab 真正写入前，根据原有投影脏矩形查找涉及的 256×256 像素块；首次碰到某块时保存旧像素，后续重复覆盖同一块不再保存。

松手时仍生成原有历史格式：累积脏矩形、before 图像和 after 图像。before 以最终图像为底，再使用保存的旧像素块覆盖对应位置；未修改的区域本来就相同。已有历史数量与字节上限、撤销和重做流程继续使用原格式。

仿制与其他调用默认保留原来的完整 COW 快照事务。增量事务的 preparePaintDirty 必须在写入像素之前调用，目前只由画笔接入。

## 过程与正确性验证

先复制基线源码到 `build/brush_perf/baseline`，建立独立测试程序；随后分别实现局部刷新和增量快照。局部刷新已消除连续绘制的背景重绘，但首次落笔仍在十几毫秒，因此继续处理撤销快照的整图复制。

测试程序为 `photosir/vanishing_point/tests/brush_check.cpp`：

- 六组固定输入笔触覆盖直径 1～500、硬度 0/100、不同透明度、透视投影、画布边缘和不同颜色。
- 在已有半透明渐变像素上绘制，逐像素 SHA256 验证新旧输出一致。
- 对每组笔触验证撤销恢复全部旧像素、重做恢复全部新像素。
- 切换工具结束笔触，再撤销；第二笔使用不同颜色，以确保确实产生新历史项。
- 连续绘制时验证背景 paint 次数为 0，绘画层实际裁剪面积小于整幅视图，初次落笔前后底层像素地址一致，未触发整绘画层复制。
- 验证缩放后重新适配图像仍对齐，撤销/重做同时刷新屏幕上的内容。
- 将局部刷新后的屏幕与强制整绘画层刷新后的屏幕比较，记录最大通道差值。

最后一项最初使用屏幕位图严格相等。对差异图分析后，普通硬件/软件显示最大只有 1 个 8 位色阶；DPR=2 的一轮仅 3 个像素达到 2 个色阶，没有超过 2 的差异。由差异位置和大小判断，属于 Qt 缩放/合成取整，而不是原始笔触像素改变。显示检查允许 DPR=1 每通道最大差 1，高 DPI 最大差 2；原始像素和撤销结果仍严格比较 SHA256，没有放宽。

## 测量方法

环境：Windows，Intel i5-10400F，16 GiB 内存，Qt 5.15.18，MSVC v142。独立测试程序为 Release，主工程另做 Debug｜x64 构建验证。

性能场景使用 4096×4096 图像、1600×1000 视图、一张平面；两种笔刷为直径 42/硬度 75/不透明度 100，以及直径 200/硬度 0/不透明度 35。输入通过 VpCanvas 的鼠标处理方法进入，包含画笔光标预览，排除系统原生鼠标干扰。

每种笔刷执行 1.7 秒，其中前 0.3 秒预热、后约 1.4 秒测量；输入定时器目标间隔 4 ms。五轮旧、新交替执行，下表为每轮指标的中位数。

```text
输入到帧提交延迟 L = frameSwapped 时间 − beforeSynchronizing 关联的最新输入开始时间
P95(L) = 排序后第 ceil(N × 0.95) 个样本
首次落笔耗时 = 鼠标按下处理函数返回时间 − 调用开始时间
更新耗时 = 鼠标移动处理函数返回时间 − 调用开始时间
有效帧间隔 I = 相邻有效 frameSwapped 时间之差
耗时下降比例 = (旧值 − 新值) / 旧值 × 100%
```

帧提交延迟是软件代理值，不是物理鼠标到显示器像素的延迟。它不包含系统输入队列和显示器响应；Qt 合并输入后关联最新输入，不能代表所有事件的排队时间。

`paintedLogicalPixels` 统计绘画项 paint 时裁剪矩形的逻辑像素面积之和；基线按整项面积乘 paint 次数计算。它是刷新区域指标，不是实测显存上传字节数，也不是精确的 CPU/GPU 像素操作次数。Qt 后端是否局部上传纹理由底层实现决定。

旧版因 GUI 线程阻塞，实际处理的输入数量更少，补点距离也更大；因此计时轨迹相同，输入次数并非相同。固定输入路径的像素等价检查单独执行，避免将异步性能轨迹的最终像素当作等价依据。

## 4K 五轮结果

| 指标 | 直径 42：旧 → 新 | 直径 200：旧 → 新 |
|---|---:|---:|
| 提交延迟 P95 | 24.654 → 4.937 ms | 24.998 → 5.327 ms |
| 提交延迟下降 | 80.0% | 78.7% |
| 首次落笔耗时 | 12.885 → 0.202 ms | 13.404 → 0.655 ms |
| 首次落笔耗时下降 | 98.4% | 95.1% |
| 有效帧间隔 P95 | 26.053 → 9.240 ms | 26.571 → 9.384 ms |
| 输入更新 P95 | 0.413 → 0.196 ms | 0.826 → 0.469 ms |
| 测量窗口内背景重绘 | 66 → 0 次 | 62 → 0 次 |
| 刷新区域逻辑像素累计 | 105,600,000 → 56,389 | 99,200,000 → 522,582 |
| 刷新区域累计面积下降 | 99.947% | 99.473% |

例如直径 42：`(24.654 − 4.937) / 24.654 = 80.0%`，按此延迟指标约加速 5 倍。

背景重绘为 0 不表示窗口不绘制：笔触图像、光标和最终场景合成仍会更新。刷新面积下降也不能直接换算为 GPU 使用率下降。

## 剩余开销和边界

笔刷径向渐变、抗锯齿、透视投影和补点仍由 CPU 执行。很小的笔刷高速长距离移动、很大的投影笔刷仍可能产生较多 dab；本次没有减少输入点、改变补点间距或降低输出分辨率。

增量事务只避免为画笔主动保存整幅 before 快照。如果其他调用者另持有绘画层 QImage 的共享引用，Qt 首次写入仍可能发生 detach。显示层已避免持有这类引用。

松手提交历史时仍分配笔触累积包围矩形的 before/after 图像。非常分散的大跨度笔触，其包围矩形可能很大；下一步可考虑让历史直接保存像素块，但那会改变现有历史格式，需单独验证。

独立绘画层增加一幅视图大小的透明缓冲；理论上 1600×1000 的 ARGB32 为 6.1 MiB，DPR=2 按物理像素约 24.4 MiB，GPU 纹理与暂存开销另计。本次没有实测峰值内存或 GPU 利用率。

## 复测

本地构建脚本为 `build/brush_perf/build.cmd` 和 `final-build.cmd`。独立配置 tests/CMakeLists.txt 时指定 Qt 路径、Release 和 `VP_BRUSH_STAGE=2`；基线源码使用 `VP_BRUSH_STAGE=0`。

```text
vp_brush_check.exe output.json 4096
vp_brush_check.exe output.json 8192
```

软件渲染设 `QT_QUICK_BACKEND=software`，高 DPI 设 `QT_SCALE_FACTOR=2`。执行时将 Qt bin 加入 PATH，保持窗口可见。程序返回 0 表示检查通过，JSON 记录失败项、像素哈希、显示通道差异和性能指标。
