# 消失点选区性能优化：实施过程与验证报告

日期：2026-10-13。工作分支：feature_vanishing_point。

四个阶段已实现并分别提交。普通选框进入现有辅助覆盖层；Ctrl 克隆使用独立临时图像；浮动选区按图像分别缓存；复制与仿制复用内容采样缓存。

本目录及报告通过本地 `.git/info/exclude` 排除，不提交 Git。测试程序和优化代码提交 Git；原始测试数据、构建日志、截图保存在本目录。

## 1. 原来的卡顿路径

- 普通选框创建、移动：鼠标更新发出内容刷新，整个背景、绘画层和所有浮动图像重新绘制；选框轮廓在绘制和命中判断时重复计算曲面映射与路径交集。
- Ctrl 克隆：先合成整张采样图，拖动中恢复/修改绘画层，再绘制全部内容。写入 COW 图像可能触发整张绘画层复制；每次移动还遍历源面与目标面组合。
- 浮动选区移动、缩放、旋转：图像与背景共用一个 QQuickPaintedItem，变换一个对象也会重绘所有静态内容。
- 反复复制：内容没有变化时仍重新分配并合成整张采样图。

## 2. 四个阶段的实现

| 阶段 | 实现 | Git 提交 |
|---|---|---|
| 1 | 缓存曲面映射、面片路径和选框轮廓；选框及变换控制点加入 AuxiliaryOverlayItem；普通选框只通知辅助层 | `dc8aad19c` |
| 2 | Ctrl 克隆只更新采样偏移，使用 FloatingContentItem 显示临时图像；松手生成原分辨率浮动选区；光标图像预览独立显示 | `34e1a4de0` |
| 3 | 每个浮动选区一个裁剪到可见范围的图像项；缓存键包括位图和投影几何；仅背景/绘画层像素改变时刷新底图 | `8f02eb86a` |
| 4 | 复制与仿制共享内容合成缓存；源面 ROI 限制取样范围；目标面交集移到内循环外；包围盒先排除不相交面片组合 | `55830b7b9` |

当前显示顺序：

```text
VpCanvas                         背景 + 绘画层
├─ FloatingContentItem           Ctrl 克隆临时图像
├─ FloatingContentItem × N       按文档顺序排列的浮动选区图像
├─ CursorPreviewItem             画笔/图章图像预览与源点标记
└─ AuxiliaryOverlayItem          平面、创建预览、选框、变换控制点
```

选区辅助线和创建预览共用管理层，但使用独立缓存批次。浮动选区的像素放在图像项中，辅助层只负责轮廓和控制点。临时 Ctrl 图像仍位于已有浮动图像下方，保持原有合成顺序。

第二阶段预览按视图缩放、DPR 和投影范围估计分辨率，取样比例不超过 1，最长边限制在约 2048 像素。图像的显示比例补偿取样缩小，位置和显示范围保持一致。松手按原始尺寸提取，原有 8192 边长和 64 MiB 输出上限继续生效。预览细节可能比最终图像柔和；最终复制/克隆输出通过像素哈希比较。

第三阶段继续使用 Qt 原有 QPainter 投影和面片接缝算法。当前变化的浮动图像仍会进行 CPU 投影绘制，但静态背景及其他浮动图像可以保留纹理。这里没有实现纯 GPU 顶点变换。

第四阶段的缓存键包括背景、绘画层的 QImage.cacheKey，以及每个浮动图像的位图键、位置、缩放、旋转和附着几何快照。仅修改平面辅助几何不改变采样内容；像素或浮动图像变化、文档替换会使缓存失效。仿制笔触保留开始时的 COW 采样快照。

ROI 目前限制到源面在图像中的包围盒，并扩展 2 像素以覆盖平滑采样。缓存首次建立/失效后仍合成整张内容图，没有实现按任意小选区按需合成背景及全部浮动图像。面片组合仍是最坏 O(F²)，本次减少了重复交集和无关候选，未引入空间索引。

## 3. 性能指标如何计算

测试工具：`photosir/vanishing_point/tests/selection_check.cpp`。输入由 GUI 线程定时驱动控制器，帧同步/提交由 QQuickWindow 信号记录。

### 输入到帧提交延迟

对每个提交帧，取该帧 `beforeSynchronizing` 时关联的最新输入：

```text
L_i = frameSwapped 时间 − 该帧关联的输入处理开始时间
P95(L) = 排序后第 ceil(0.95 × N) 个样本
耗时下降比例 = (旧 P95 − 新 P95) / 旧 P95 × 100%
耗时加速倍数 = 旧 P95 / 新 P95
```

这表示输入进入控制器到 Qt 帧提交的软件延迟代理值。它包含控制器计算、同步、相关绘制与提交等待，不包含操作系统输入队列、物理鼠标采样、显示器扫描和像素响应。

Qt 会合并多个输入到同一帧。指标关联最新输入，因此不能代表所有输入事件的排队时间；不能根据该数值声称真实鼠标到像素延迟。每轮至少要求 20 个有效帧，排除窗口被遮挡后没有实际呈现的情况。

### 帧间隔与内容层重绘

```text
I_i = 本次有效 frameSwapped 时间 − 上次有效 frameSwapped 时间
内容层重绘次数 = 测量窗口内 VpCanvas.paint 调用次数
内容层重绘减少比例 = (旧次数 − 新次数) / 旧次数 × 100%
```

I 的 P95 用来观察跟随是否平稳。60 Hz 的一帧预算约 16.67 ms，可作为判断目标，但本测试有效帧间隔并非显示器刷新率，也不是所有 Qt 提交帧的全量统计。

内容层重绘为 0，只表示背景和绘画层没有重新栅格化；辅助层、活动图像层及窗口合成仍有工作。不能把它解释为整个窗口没有渲染、CPU/GPU 使用率为 0 或所有纹理上传均已消除。

### 输入更新与重复复制

`updateP95Ms` 记录 pointerMove 控制器调用的耗时 P95；`repeatCopyMs` 为预热一次后连续复制 8 次的总耗时除以 8。

普通选框和浮动操作的 GUI 更新耗时略增加，因为现在在 GUI 更新时同步独立层和缓存键。收益主要来自移除背景/其他图像的重复绘制，应结合帧提交延迟判断，不只比较 pointerMove 函数耗时。

## 4. 对照条件

- 基线：`a7936721e`，已经包含此前的创建预览和平面辅助层优化，尚未包含这四阶段选区优化。
- 在改动前将源码复制到 `build/selection_perf/baseline`，同一套输入与检查程序分别链接旧、新源码。
- Windows；Intel Core i5-10400F；16 GiB 内存；Qt 5.15.18；MSVC v142。
- 独立测试程序 Release 构建，Qt Quick 默认硬件场景图，DPR=1，1600×1000 测试视图，4096×4096 图像。
- 每个操作 1.7 秒，前 0.3 秒预热，后约 1.4 秒统计；定时输入目标间隔 4 ms，过载时实际输入数量会降低。
- 旧、新各 5 轮，轮次间交替执行顺序；下表取每轮 P95 的中位数，重绘次数也取中位数。这里不是把所有帧混合后再算 P95。
- 内容交互性能场景使用一张平面和均匀背景；正确性场景另外使用透明渐变图像、两个共享曲面面片、非均匀透视和不同克隆偏移。性能结果不能直接推广到大量复杂面片或整套主程序的所有负载。

## 7. 内存与后续边界

一份 ARGB32 合成缓存的理论像素费用：`宽 × 高 × 4` 字节，4K 为 64 MiB，8K 为 256 MiB。共享 QImage 引用本身不复制像素。仿制冻结快照与当前缓存内容不同时，可能各持有一份像素；这里没有实测进程峰值内存，也没有把缓存当作内存降低指标。

当前主要剩余开销是活动浮动图像的 CPU 投影、内容变更后的首次整图采样合成、多面片组合和很大选区松手时的原分辨率提取。进一步优化可以围绕实际选区 ROI 合成、面片空间索引、复用源纹理的场景图投影展开；先以本报告的同一测试轨迹复测，避免用缩小最终输出换取表面上的提升。

## 8. 复测方式

本机脚本位于 `build/selection_perf`，不提交 Git：

```text
build.cmd 4               从 Qt/MSVC 环境构建当前四阶段检查
baseline.cmd              链接改动前源码快照
final-build.cmd           构建新旧选区检查及创建/平面回归
```

可独立配置 tests/CMakeLists.txt，指定 Qt 的 CMAKE_PREFIX_PATH、Release 配置和 `-DVP_SELECTION_STAGE=4`。旧源码检查使用 stage=0 和 VP_SOURCE_DIR 指向基线快照。

运行格式：

```text
vp_selection_check.exe output.json 4096
vp_selection_check.exe output.json 8192
```

软件路径设 `QT_QUICK_BACKEND=software`；高 DPI 设 `QT_SCALE_FACTOR=2`。把 Qt bin 加入 PATH，执行时保持窗口可见。程序返回 0 表示检查通过，JSON 中含 passed、failures、各操作性能指标及输出像素哈希。
