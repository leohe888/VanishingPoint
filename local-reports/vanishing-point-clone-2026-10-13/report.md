# 消失点图章绘制性能优化报告

日期：2026-10-13。基线：画笔优化完成后的 `508c5b0e9`。本次提交：`46f9e1c1f`。

本报告、测试数据和日志保存在本地排除目录，不提交 Git。

## 定位结果

图章没有接入此前画笔的局部刷新和增量撤销事务。每次移动仍发送通用内容刷新，重新绘制整个绘画层；首次落笔保存绘画层完整 COW 快照，写入时复制整层像素。

另一个显著开销在 CloneTool::renderDab：每个补点逐像素计算目标面逆投影、源面正向投影、笔刷遮罩和四邻域双线性取样。相邻补点高度重叠，光标预览又重复这些计算。图章变大后，单纯分层仍不足以消除这一部分开销。

## 实现

1. 图章接入 beginPaintTransaction(true)，每个 dab 写入前调用 preparePaintDirty，沿用画笔的 256×256 旧像素块快照。最终仍写入原有脏矩形 before/after 历史格式。
2. beginClone/moveClone 发送 paintRepaintRequested(dirty)，只刷新绘画项的可见脏区域，避免每次移动刷新整幅绘画层。
3. 图章预览裁到投影笔刷附近。源点十字使用独立的小图像项，避免两个相距较远的点撑出一块很大的透明预览纹理。
4. 双线性取样直接读取 constBits 和行跨度，替代每个邻居的 QImage.pixel 与 QRect.contains 调用。边界判断、四邻域顺序、权重乘法和 qRound 顺序保留。
5. 相同尺寸的 dab 和预览位图复用；复用前仍清零透明像素。
6. 增加投影坐标缓存：32×32 像素一块，最多 128 块，由 QCache 淘汰旧块。逐像素坐标只在首次需要时计算，相邻补点和预览共用缓存。

坐标缓存保存目标展开坐标、源画布坐标与映射有效状态，不缓存颜色。缓存键包含两套投影矩阵和偏移；换面、换源映射或偏移变化时清空。取样源图像改变后，仍从当前冻结源图读取颜色，因此可以复用相同几何的坐标而不会复用旧颜色。

每个缓存块约 33 KiB，128 块的坐标数据理论上约 **4.125 MiB**，另有少量缓存管理开销。很大的投影范围若超过 128 个块，直接使用原有逐像素映射路径，避免块缓存反复淘汰。透视有效性和地平线检查仍使用原来的映射函数。

## 对照与验证过程

先复制基线源码到 `build/clone_perf/baseline`，同一测试程序分别链接旧、新实现。初步局部刷新通过后，发现大图章仍受逐像素映射限制，随后加入坐标缓存。

正式性能测量在主工程构建结束后执行，避免编译负载干扰。初步 1.4 秒测量中，慢速基线有时不足 20 个有效帧，因此正式测量改为每项 **3.7 秒，前 0.3 秒预热、后约 3.4 秒统计**。旧、新各五轮，交替执行先后顺序。

性能场景使用 4096×4096 图像、1600×1000 视图、一张非均匀透视平面，展开面与画布四边形不同。两种图章分别为直径 42/硬度 75/不透明度 100，以及直径 200/硬度 0/不透明度 35。定时输入目标间隔 4 ms，通过 Canvas 鼠标处理函数进入，包含光标预览。

固定输入正确性检查另外使用带颜色的背景和已有半透明像素，覆盖直径 1～500、硬度 0/100、不同透明度、对齐与非对齐模式、画布边缘、换源和第二笔。十二组输出 SHA256 与基线一致。

同时检查：

- 笔触改变像素，撤销恢复全部旧像素，重做恢复全部新像素。
- 切换工具结束笔触，随后可以撤销该笔。
- 同一笔内采样合成次数不增加，源图保持冻结。
- 新版落笔前后绘画层底层像素地址不变，没有因图章撤销快照发生整层 detach。
- 局部刷新、缩放后重新适配、撤销/重做的屏幕内容正常刷新。
- 局部刷新与强制整绘画项刷新进行屏幕对照；原始像素仍严格比较哈希。

屏幕缩放和合成允许每个 8 位通道最大 **2 个色阶**的取整差异。4K 普通与软件路径实测最大 1；8K 缩小显示的一轮有 4 个像素达到 2，没有超过 2 的差异。该显示容差没有用于笔触输出或撤销像素检查。

## 性能指标与计算

```text
L = frameSwapped 时间 − beforeSynchronizing 关联的最新输入开始时间
P95(L) = 排序后第 ceil(0.95 × N) 个样本
延迟下降比例 = (旧 P95 − 新 P95) / 旧 P95 × 100%
输入更新耗时 = Canvas 鼠标移动处理函数返回时间 − 调用开始时间
有效帧间隔 = 相邻有效 frameSwapped 时间之差
```

L 是软件输入到帧提交的代理值，不包含物理鼠标采样、系统输入排队和显示器响应。Qt 合并输入后关联最新输入，不能表示所有输入事件的排队时间。

旧版因阻塞处理的输入更少，每次补点距离也更大；两版使用同一时间轨迹，但实际输入次数不同。因此异步性能轨迹的最终像素不作为等价依据，像素等价使用另一组固定输入检查。

测试环境：Windows，Intel i5-10400F，16 GiB 内存，Qt 5.15.18，MSVC v142；独立测试程序 Release，DPR=1，默认硬件场景图。主工程另做 Debug｜x64 构建验证。

## 4K 五轮结果

下表取五轮各项统计的中位数，不是把全部帧混在一起算 P95。

| 指标 | 直径 42：旧 → 新 | 直径 200：旧 → 新 |
|---|---:|---:|
| 提交延迟 P95 | 16.130 → 5.195 ms | 48.432 → 8.036 ms |
| 提交延迟下降 | 67.8% | 83.4% |
| 输入更新 P95 | 2.043 → 0.502 ms | 27.953 → 2.643 ms |
| 有效帧间隔 P95 | 16.897 → 9.218 ms | 74.549 → 10.779 ms |
| 起笔处理耗时 | 43.355 → 30.012 ms | 47.510 → 18.469 ms |

例如直径 200：`(48.432 − 8.036) / 48.432 = 83.4%`，按这一延迟指标约加速 **6.0 倍**。

**首次采样合成仍有开销。** 图章需要将背景、绘画层及浮动图像合成为冻结取样源。上述起笔耗时包含当时取样缓存是否命中，不能解释为撤销快照单独耗时，也不能承诺像画笔那样每次起笔都低于 1 ms。

五轮数据见 [comparison.json](comparison.json) 及 `final-baseline-round*.json`、`final-optimized-round*.json`。

## 刷新区域补测

基线已继承画笔的独立 PaintLayerItem，背景本身也已经缓存。因此背景 paint 为 0 在两版都成立，本次收益应比较绘画项刷新区域。

最初测试沿用单层画布计数，基线绘画项面积字段没有记录到子项，不能使用该字段。本次已修正工具，让两版都直接读取 PaintLayerItem 的裁剪面积，并单独补测同一轨迹。五轮的提交延迟和输入更新统计不受这一计数修正影响。

| 单轮补测：累计逻辑像素刷新面积 | 旧 | 新 | 面积下降 |
|---|---:|---:|---:|
| 直径 42 | 355,200,000 | 134,525 | 99.962% |
| 直径 200 | 115,200,000 | 1,111,434 | 99.035% |

数据见 `area-baseline.json`、`area-optimized.json`。这是绘画项 paint 时裁剪矩形面积的累计值，不是精确 CPU/GPU 操作量，也不是实测纹理上传字节数。新版帧数更多，但每次只刷新很小的区域。

## 剩余边界

双线性取样、遮罩、混合和未命中的透视坐标仍由 CPU 计算。极端放大的投影范围、缓存容量之外的笔触以及首次内容合成仍可能较慢；本次没有通过跳过输入、减少补点或降低最终输出分辨率换取速度。

采样合成仍是整图缓存，4K 一份 ARGB32 为 64 MiB，8K 为 256 MiB。冻结源快照和历史像素块会额外占用内存；本次未测进程峰值内存或 GPU 利用率。下一步若继续优化首次起笔，可研究按实际取样范围合成源图，需要保留跨面、透明边缘和笔触冻结语义。

## 复测方式

测试源：`photosir/vanishing_point/tests/clone_check.cpp`。本机脚本：`build/clone_perf/build.cmd` 和 `final-build.cmd`，不提交 Git。

配置 tests/CMakeLists.txt 时设 Qt 路径、Release，以及新版 `VP_CLONE_STAGE=2`；基线设 stage=0 并将 VP_SOURCE_DIR 指向基线源码。

```text
vp_clone_check.exe output.json 4096
vp_clone_check.exe output.json 8192
```

软件路径设 `QT_QUICK_BACKEND=software`，高 DPI 设 `QT_SCALE_FACTOR=2`。执行时将 Qt bin 放入 PATH，保持测试窗口可见。JSON 包含失败项、输出哈希、屏幕通道差异、帧数和性能指标。
