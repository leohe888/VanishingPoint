# 消失点创建平面：橡皮筋预览性能优化报告

日期：2026-10-13。范围仅为创建平面时的连线与角点预览。

## 问题与证据

原实现的调用路径：`hoverMoveEvent → updateCursorPoint → update() → VpCanvas::paint → renderContent + renderGuides → 纹理上传与窗口提交`。

鼠标移动时只需改变一至两条预览连线，但无区域参数的 `update()` 会让整个 QQuickPaintedItem 内容重新绘制。背景、绘画层、浮动选区和已有平面也随之重复绘制。该阶段不执行创建平面的透视求解；它不是本次主要优化对象。

局部处理耗时、实际内容层重绘次数、帧提交延迟和预览更新间隔一起验证这一判断。仅测鼠标处理函数或橡皮筋绘线函数，不能反映最终跟手程度。

## 修改过程

1. 在修改前保留当前消失点源码快照，基线提交为 `1d8b3fc41d1f3b5311f6a1f49012b1ff5604319f`。
2. 新增 `CreationPreviewItem`，将创建连线、已点击角点和鼠标端点移到独立子覆盖层。
3. 硬件场景图路径使用 `QSGGeometryNode + QSGVertexColorMaterial`，更新屏幕坐标中的少量三角形顶点；线宽保持 2 个逻辑像素，并以 1 个设备像素的透明边缘平滑斜线。顶点颜色采用预乘 alpha。
4. 鼠标移动与离开画布只更新覆盖层；点击、工具切换、文档变化、缩放、滚动等仍同步相应状态。
5. 软件场景图不绘制这种自定义几何节点，因此提供独立透明 `QQuickPaintedItem` 覆盖层。它保留 QPainter 绘线，仍不重画背景内容层。
6. 使用显式的鼠标在画布内状态，修复图像坐标 `(0,0)` 被当作空点而隐藏端点的情况。
7. 新增独立 Qt 5.15 性能与交互检查程序，同一程序可指定旧源码或新源码目录。

开发检查中，发现软件后端几何节点不显示，补充并验证了上述兼容路径。初期部分测量窗口被遮挡后停止出帧，这类样本全部排除。最终测试窗口保持可见、不抢键盘焦点，并要求每个角点阶段至少产生 50 个有效预览帧。还采用完整重建，避免本机 Ninja/MSVC 增量构建中头文件依赖未更新造成旧对象文件混入。

## 测量环境和方法

- Windows；Intel Core i5-10400F，6 核 12 线程；AMD Radeon RX 640，驱动 31.0.12020.1。系统报告当前刷新率 200 Hz；窗口实际出帧节奏见结果，不将其假定为 60 Hz。
- Qt 5.15.18 `msvc2019_64`，MSVC v142；性能程序使用 Release，主工程验证使用 Debug x64。
- 性能程序直接链接主工程中的消失点源文件，以独立 QQuickWindow 运行；它不是原 Qt 6 demo。
- 正式对比：OpenGL 后端、DPR=1、1600×1000 逻辑像素窗口；4096×4096 与 8192×8192 图像分别运行 5 轮新旧配对测试。每轮交替执行顺序，避免始终先测旧版。
- 图像为灰色底与固定斜线；使用相同的实时轨迹方程和 4 ms 精确定时器设置。卡顿会使旧版实际处理的定时器回调更少，因此两版实际接收的坐标样本数量可能不同。
- 每轮依次点击 1、2、3 个角点。各阶段持续 2.5 秒，前 0.5 秒预热，后 2 秒采样；每轮有效测量时长合计约 6 秒。
- 回放直接进入 VpCanvas 的 hover 处理路径；屏蔽测试窗口的偶然桌面鼠标/键盘事件。测量不包含操作系统将真实鼠标事件送到程序之前的等待。
- 使用同一个 QElapsedTimer 单调时钟。在 `beforeSynchronizing` 捕获该帧使用的最新输入编号和接收时间，使用直接连接的 `frameSwapped` 记录该帧提交时间，避免排队到 GUI 线程的信号槽增加测量误差。
- 对被新坐标覆盖、没有单独显示的输入不逐个统计延迟。因此必须同时报告预览更新间隔，避免“最新输入延迟很低，但很久才更新一次”的误判。
- 截图与功能检查在计时停止后执行；功能检查运行不纳入正式性能对比。

## 指标定义

对于实际提交的第 j 帧，i 为该帧同步时消费的输入编号：

```text
帧提交延迟 L[j] = t_submit[j] - t_input[i]
预览更新间隔 I[j] = t_submit[j] - t_submit[j-1]
```

更新间隔仅在同一角点阶段内计算，不将点击与预热之间的间隙算作卡顿。

```text
P95 = 对 N 个值排序，取第 ceil(0.95 × N) 个值（从 1 开始）
长停顿比例 = 更新间隔 > 33.333333 ms 的次数 / 有效更新间隔数 × 100%
延迟降低率 = (旧版 P95 - 新版 P95) / 旧版 P95 × 100%
加速倍数 = 旧版 P95 / 新版 P95
```

33.33 ms 是固定的长停顿统计阈值，相当于两个 60 Hz 周期，不代表本机实际掉帧次数。内容层绘制耗时为覆盖 `VpCanvas::paint` 的壁钟时间，包含 QPainter 绘制工作，不包含完整后续纹理上传和显示等待，也不是 CPU 利用率。

正式结果表采用“各轮 P95 的中位数”，同时附逐轮数据和范围；不将多个轮次直接混为单一 P95。

## 复现方式

测试源码：`photosir/vanishing_point/tests/creation_preview_check.cpp`。先进入 VS 2019 x64 编译环境，再执行：

```powershell
cmake -S photosir/vanishing_point/tests -B build/preview-check -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=D:/Software/Qt/5.15.18/msvc2019_64
cmake --build build/preview-check --clean-first
$env:PATH = 'D:\Software\Qt\5.15.18\msvc2019_64\bin;' + $env:PATH
& build/preview-check/vp_creation_preview_check.exe result.json 4096 preview.png functional
```

指定 `-DVP_SOURCE_DIR=旧版消失点源码目录` 可构建旧版基准；旧版不能传 `functional` 参数，因为像素检查包含本次新增覆盖层和原点修复。

软件后端复现设置 `$env:QT_QUICK_BACKEND='software'`；高 DPI 检查设置 `$env:QT_SCALE_FACTOR='2'`。改变后端/缩放时需重新启动检查程序。

本机过程脚本、构建日志和旧源码快照保留于 `build/rubberband_perf/`。最终逐帧原始 JSON、逐轮汇总 CSV、截图与本报告另存于本报告所在目录。

## 结论适用范围

本次结果证明：在上述主工程消失点组件与固定场景下，将橡皮筋从内容层重绘中分离，可显著降低软件侧帧提交延迟和更新间隔。鼠标移动期间内容层不再因橡皮筋变化重绘。

测试没有测量真实鼠标硬件到屏幕像素显示的完整延迟，也没有包含主程序其他界面和后台任务造成的额外阻塞。若完整主界面仍存在明显停顿，应使用同样的编号关联和阶段计时继续定位；不能将本报告的毫秒数直接视为完整主程序在任何机器上的保证值。
